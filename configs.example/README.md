# Example Configuration Files

This directory contains example configuration files for reference. These files are **NOT used directly** by the deployment system - they serve as templates and documentation.

## Docker Compose Examples

### Single Container Setup

**File:** `docker-compose.yml`

Basic setup with one web service. Best for simple applications that use external databases or managed services.

**Required files in your app directory:**
```
~/your-app-dir/
├── docker-compose.yml      # Copy from docker-compose.yml
├── .env                    # Copy from .env.example
└── .env.docker            # Copy from .env.docker (optional)
```

### Multi-Container Setup

**File:** `docker-compose.multi-container.yml`

Complete setup with web service, PostgreSQL database, and Redis cache. Best for applications that need local database and caching.

**Required files in your app directory:**
```
~/your-app-dir/
├── docker-compose.yml      # Copy from docker-compose.multi-container.yml
├── .env                    # Copy from .env.example
└── .env.docker            # Copy from .env.docker
```

## Environment Variable Files

### `.env.example`

**Purpose:** Docker Compose configuration variables

Contains variables that Docker Compose uses:
- `DOCKER_IMAGE` - Your DockerHub image name
- `DOCKER_CONTAINER_NAME` - Container name for the web service
- `COMPOSE_PROJECT_NAME` - Project name prefix for all resources
- `POSTGRES_*` - Database credentials (for multi-container setup)

**Usage:**
```bash
cp .env.example ~/your-app-dir/.env
nano ~/your-app-dir/.env  # Edit with your values
```

### `.env.docker`

**Purpose:** Application runtime environment variables

Contains variables that your application needs at runtime:
- `NODE_ENV`, `PORT` - Application settings
- `DATABASE_URL`, `REDIS_URL` - Connection strings
- `API_KEY`, `JWT_SECRET` - Application secrets
- `LOG_LEVEL` - Logging configuration

**Usage:**
```bash
cp .env.docker ~/your-app-dir/.env.docker
nano ~/your-app-dir/.env.docker  # Edit with your values
```

## Understanding COMPOSE_PROJECT_NAME

`COMPOSE_PROJECT_NAME` controls the naming of Docker resources:

**Without setting it:** Resources use directory name as prefix
```bash
# In directory ~/gm-frontend/
# Resources will be prefixed with: gm-frontend_
```

**With COMPOSE_PROJECT_NAME=gymmate:**
```bash
# Resources will be prefixed with: gymmate_
```

**What it affects:**

| Resource Type | Without explicit name | With COMPOSE_PROJECT_NAME=gymmate |
|--------------|----------------------|-----------------------------------|
| Container (web) | `gm-frontend_web_1` | `gymmate_web_1` |
| Container (db) | `gm-frontend_db_1` | `gymmate_db_1` |
| Network | `gm-frontend_default` | `gymmate_network` (if explicitly named) |
| Volume | `gm-frontend_postgres_data` | `gymmate_postgres_data` (if explicitly named) |

**Note:** If you use `container_name:` in docker-compose.yml, it overrides the project name prefix for that specific container.

## System Service Files

These files are **generated automatically** by the setup scripts:

- `web.service` - Systemd service for running Docker Compose (example only)
- `webhook.service` - Systemd service for webhook listener (example only)
- `cloudflared.yml` - Cloudflared tunnel configuration (example only)
- `hooks.yml` - Webhook listener configuration (example only)

**Do not copy these manually!** They are generated by:
- `scripts/create-service-files.sh` - Generates systemd services
- `scripts/create-config.sh` - Generates cloudflared config
- `scripts/create-hook-config.sh` - Generates webhook config

## Quick Start Examples

### Single Container

```bash
# On your server
cd ~/your-app-dir

# Copy example files
cp ~/simple-cicd/configs.example/.env.example .env
cp ~/simple-cicd/configs.example/.env.docker .env.docker
cp ~/simple-cicd/configs.example/docker-compose.yml docker-compose.yml

# Edit with your values
nano .env
nano .env.docker

# Test
docker compose up
```

### Multi-Container

```bash
# On your server
cd ~/your-app-dir

# Copy example files
cp ~/simple-cicd/configs.example/.env.example .env
cp ~/simple-cicd/configs.example/.env.docker .env.docker
cp ~/simple-cicd/configs.example/docker-compose.multi-container.yml docker-compose.yml

# Edit with your values
nano .env
nano .env.docker

# Test
docker compose up
```

## Important Notes

1. **Never commit .env files to git** - Add them to `.gitignore`
2. **Use strong passwords** for database credentials in production
3. **Test locally first** before deploying to production
4. **Backup your data** before making changes to running services
5. **Use secrets management** for sensitive values in production (e.g., Docker Secrets, Vault)
